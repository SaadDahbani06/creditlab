# Model Card: CREDITLAB next-month default model

Tables between `BEGIN`/`END` markers are generated by `creditlab report` from the saved artifacts.

## Model details

- **Task:** estimate $P(\text{default on next month's payment} \mid \text{April–September 2005 account history})$.
- **Candidates:** DummyClassifier (base rate), L2 logistic regression, XGBoost (`hist` trees). Each
  was also tested with sigmoid and isotonic calibration fitted on training out-of-fold predictions.
- **Selected (primary) model:** chosen on validation by log loss. See the table below.
- **Inputs (19 source columns + 9 engineered):** `LIMIT_BAL`, `PAY_0`, `PAY_2`–`PAY_6`,
  `BILL_AMT1`–`6`, `PAY_AMT1`–`6`, plus row-wise engineered utilisation, payment-ratio and
  delinquency-count features (`docs/DATA_DICTIONARY.md`).
- **Excluded inputs:** `ID`; `SEX`, `AGE`, `MARRIAGE` (sensitive); `EDUCATION` (proxy concern).
- **Artifacts:** `artifacts/models/*.joblib`, `artifacts/models/training_metadata.json`
  (hyperparameters, training-ID hash), `artifacts/metrics/run_manifest.json` (environment, seed,
  config).

## Intended use

Research and education: studying discrimination, calibration and how PD estimates propagate into
hypothetical portfolio-loss distributions.

**Out of scope:** any real credit, pricing, limit or account-management decision; any
applicant population; any period other than 2005 Taiwan; any use of the model's outputs as
reasons about an individual.

## Data

UCI dataset 350 (CC BY 4.0), 30,000 existing accounts. Stratified client-level split of
60/20/20 (train/validation/test), fixed seed. Persisted in `data/processed/splits.csv`.

## Calibration

Neither calibration method met the selection rule on validation: lower log loss, Brier not
higher, and a bootstrap CI for the improvement below zero. This rule was tightened after a first
run; see `docs/DECISIONS.md` D9. The raw models were kept. Sigmoid
calibration of the logistic model changed validation log loss by about −0.00004, which is not
distinguishable from zero. Both calibrations *worsened* XGBoost on validation.

## Caveats

See `docs/LIMITATIONS.md`. The most important: existing-account selection bias, no out-of-time
test, undocumented status codes, moderate discrimination, and the fact that excluding sensitive
attributes does not remove group differences.
